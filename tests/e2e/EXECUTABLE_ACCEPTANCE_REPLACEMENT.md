# M4 Executable Acceptance Replacement

M4 converts the project from narrative acceptance toward machine-checkable runtime evidence.

The final certification rule is simple: a test that only says what should be checked is not enough. A final acceptance test must execute commands, verify database state, verify audit evidence, and prove tenant/RBAC/state-transition behavior where the workflow requires it.

## Required local runtime inputs

- `pnpm-lock.yaml` generated by M1
- live PostgreSQL `DATABASE_URL`
- live API `NEXORA_API_BASE_URL`
- completed M2 database migration/seed gate
- completed M3 Docker/runtime preflight

## Blocking rule

`M4_ENFORCE_EXECUTABLE_ACCEPTANCE=1` turns narrative-only requirements into certification failures. This prevents production release from being approved by documentation-only checks.
