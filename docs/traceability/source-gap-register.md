# NEXORA ERP — Contract Fidelity / Source Gap Register

baseline freeze must distinguish **what the PDF actually locks** from details it does not fully print.

## GAP-API-001 — Complete field-level schemas are not printed for every endpoint

The specification states that exact payload fields live in `shared/src/contracts`, and it prints a full route catalog plus selected request/response examples. It does **not** provide a complete request/response JSON schema for every endpoint in the catalog.

### baseline freeze handling

- Lock every printed HTTP method.
- Lock every printed `/api/v1` path.
- Lock every printed purpose.
- Lock every printed permission literal.
- Lock every printed note/state/transaction requirement.
- Lock global response/error/pagination/versioning conventions.
- Lock the source-provided concrete payload examples.
- Do not invent omitted fields and incorrectly label them as source-locked.
- During implementation, shared Zod contracts must be derived from the source's entity/business rules without contradicting any locked item.

## GAP-NUM-001 — Functional numbering jumps from §96 to §101

The source contains no numbered functional sections 97–100 in the parsed document. baseline freeze preserves the original numbering instead of manufacturing missing sections.

## GAP-PERM-001 — Endpoint catalog contains permission literals not separately listed in §11.1

The endpoint catalog uses more granular permission literals than the summarized permission catalog. baseline freeze preserves both:
- the explicit §11.1 / Appendix F permission catalog; and
- every additional literal appearing in the locked endpoint table.

No literal is renamed merely to make the two lists look uniform.

## GAP-FE-APPENDIX-G-001 — Earlier passes do not close the latest frontend addendum

R0 found that earlier frontend-workflow gates were built against the older source baseline and do not, by themselves, satisfy Appendix G v1.2 from the 90-page blueprint.

### R0 handling

- Treat Appendix G as active source authority, not optional documentation.
- Do not claim frontend completion until shadcn/ui primitives, NEXORA component wrappers, React Hook Form + Zod forms, TanStack Table grids, centralized API/query hooks, route-group shells, screen contracts and complete create/edit/detail/command workflows exist.
- Do not claim portal/PWA completion until the Fastify route `POST /api/v1/portal/technician/offline-sync` exists with technician scope, tenant/branch enforcement, idempotency, replay/conflict handling and transaction/audit behavior.
- Do not allow Next.js route handlers to become a second ERP business API.

## GAP-RUNTIME-R0-001 — R0 rebases source authority only

R0 is intentionally a source-of-truth remediation pass. It does not generate the missing `pnpm-lock.yaml`, install dependencies, add frontend packages, implement new route handlers or certify Docker runtime.

### R0 handling

- Carry the lockfile/runtime/frontend/offline-sync blockers forward to R1+.
- Mark R0 as complete only when source authority and mandatory Appendix G gap tracking are updated.

## GAP-LOCKFILE-R1-001 — R1 requires registry access for real lockfile generation

R1 cannot honestly fabricate `pnpm-lock.yaml`. The lockfile must be generated by pnpm from the registry using the exact root workspace dependency graph.

### R1 handling

- Add stricter R1 source-side checks, CI lockfile policy enforcement and cross-platform certification scripts.
- Keep the release blocked until a connected developer machine generates `pnpm-lock.yaml` and runs the full R1 certification command.
- Do not claim Docker runtime, dependency-backed tests or production readiness until the real lockfile exists.
